# Small-Language-Model
A lightweight reimplementation of nanoGPT, recreated for training and experimenting on the TinyStories dataset.

# Training a GPT-2 Model on TinyStories

This project details the complete pipeline for training a small, GPT-2-style transformer model from scratch on the "TinyStories" dataset. It covers data preparation, tokenization, efficient data loading, model architecture, and the training loop.

## 1\. Dataset Preparation: TinyStories


We use the `roneneldan/TinyStories` dataset, a collection of short stories generated by GPT-3.5 and GPT-4. This dataset is quite large, containing **approximately 2.1 million stories in its training set** and **about 22,000 stories in its validation set**. The stories are intentionally designed to be simple enough for a small language model to learn, using a restricted vocabulary and simple grammar. This makes them ideal for training models that can generate coherent and grammatically correct English.

This dataset was introduced in the paper:

> **Tinystories: How small can language models be and still speak coherent english?**
> Eldan, Ronen and Li, Yuanzhi
> *arXiv:2305.07759*

The code automatically downloads this dataset using the `datasets` library from Hugging Face.

## 2\. Tokenization: Tiktoken and GPT-2 BPE

Before the model can process text, we must convert it from strings of characters into sequences of numbers (tokens). We use `tiktoken`, OpenAI's fast BPE tokenizer, specifically with the `"gpt2"` encoding.

### What is Byte-Pair Encoding (BPE)?

BPE is a data compression algorithm that iteratively merges the most frequent pair of adjacent "bytes" (or characters) in a vocabulary. In the context of tokenization:

1.  **Initialization:** The initial vocabulary consists of all individual bytes (256 of them, covering all ASCII and extended characters).
2.  **Learning Merges:** The tokenizer is trained on a large corpus. It counts the frequency of all adjacent pairs of tokens (initially, just bytes).
3.  **Iteration:** It takes the most frequent pair (e.g., `'t'` and `'h'`) and merges them into a new, single token (e.g., `'th'`). This new token is added to the vocabulary.
4.  **Repeat:** This process repeats for a fixed number of merges (e.g., 50,000 times). The vocabulary grows to include common character sequences (like `'th'`, `'ing'`) and eventually whole words (like `' the'`, `' and'`).

### How GPT-2's BPE (via Tiktoken) Works

The "gpt2" tokenizer is a specific BPE implementation. A key feature is that it **operates on the byte level**. This means it can tokenize *any* string of text, even ones with emojis or multiple languages, without ever encountering an "unknown" character.

**Example:**

1.  **Input Text:** `"A little girl"`
2.  **Encode (`enc.encode_ordinary`):** This function converts the string into a list of token IDs.
      * `"A"` might become `[32]`
      * `" little"` (note the preceding space) might become `[539]`
      * `" girl"` might become `[2811]`
3.  **Output IDs:** `[32, 539, 2811]`
4.  **Decode (`enc.decode`):** This converts the IDs back to a string.
      * `enc.decode([32, 539, 2811])` -\> `"A little girl"`

The code uses `enc.encode_ordinary` which ignores any special tokens (like `<s>` or `[PAD]`) and just tokenizes the raw text. The vocabulary size for GPT-2 is **50,257**.

## 3\. Data Processing and Storage

Training on a large text dataset requires careful memory management. We cannot load the entire tokenized dataset into RAM.

### Tokenizing the Dataset

The `process` function is applied to every example in the dataset:

```python
def process(example):
    ids = enc.encode_ordinary(example['text']) # encode_ordinary ignores any special tokens
    out = {'ids': ids, 'len': len(ids)}
    return out
```

This maps each story (e.g., `"Once upon a time..."`) to a dictionary containing its token IDs (e.g., `[4981, 1374, 257, 640, ...]`) and the sequence length.

### Efficient Storage with `np.memmap`

Instead of storing these token lists in RAM, we write them to binary files (`train.bin`, `validation.bin`) using `numpy.memmap`.

1.  **Calculate Total Length:** We first sum the `len` of all stories to find the total number of tokens in the split (e.g., `arr_len = 450,000,000`).
2.  **Create Memmap File:** `np.memmap(filename, dtype=np.uint16, mode='w+', shape=(arr_len,))` creates a file on your hard drive that *acts* like a massive NumPy array. The `dtype=np.uint16` is a memory optimization: since the vocab size (50,257) is less than $2^{16}$ (65,536), we can store each token ID as an unsigned 16-bit integer (2 bytes) instead of the default 64-bit integer (8 bytes).
3.  **Write in Batches:** The code iterates through shards of the dataset, tokenizes them, concatenates the token IDs (`arr_batch`), and writes this batch directly into the memmapped array (`arr[idx : idx + len(arr_batch)] = arr_batch`).

The result is a single, massive file (e.g., `train.bin`) that contains all token IDs from all stories, concatenated one after another. This file can be many gigabytes, but it **does not occupy RAM**. The operating system will intelligently load only the parts of the file that are being read at any given moment.

## 4\. Creating Training Batches

The `get_batch` function is responsible for loading data from our `.bin` file and preparing it for the GPU.

### Input/Output (X/Y) Pairs

The model is trained to predict the **next token** in a sequence. We create input/target pairs (`x` and `y`) from a continuous chunk of text.

  * **Context Size (`block_size`):** This is the maximum sequence length the model can handle at one time. In the code, `block_size = 128`.
  * **Input `x`:** A sequence of tokens of length `block_size`.
  * **Target `y`:** The same sequence as `x`, but **shifted one position to the left**.

If a random chunk of tokens from `train.bin` is:
`[101, 502, 89, 10, 24, 99, 304]`

And our `block_size` is 4:

  * `x` (input) = `[101, 502, 89, 10]`
  * `y` (target) = `[502, 89, 10, 24]`

The model's task is:

  * Given `[101]`, predict `502`.
  * Given `[101, 502]`, predict `89`.
  * Given `[101, 502, 89]`, predict `10`.
  * Given `[101, 502, 89, 10]`, predict `24`.

(The causal mask, explained later, ensures the model only uses past tokens).

### Batching Example (Batch Size = 4, Context Size = 4)

The `get_batch` function repeats this process `batch_size` times.

  * `batch_size = 4`
  * `block_size = 4`

It will randomly select 4 starting positions in `train.bin` and stack the resulting `x` and `y` tensors.

**Input `x` (Shape: `[4, 4]`)**

```
[
  [t1,  t2,  t3,  t4 ],  # Sample 1
  [tA,  tB,  tC,  tD ],  # Sample 2 (from a different random part of the file)
  [tX,  tY,  tZ,  tW ],  # Sample 3
  [tP,  tQ,  tR,  tS ]   # Sample 4
]
```

**Target `y` (Shape: `[4, 4]`)**

```
[
  [t2,  t3,  t4,  t5 ],  # Sample 1 targets
  [tB,  tC,  tD,  tE ],  # Sample 2 targets
  [tY,  tZ,  tW,  tV ],  # Sample 3 targets
  [tQ,  tR,  tS,  tT ]   # Sample 4 targets
]
```

### Efficient Data Loading: `pin_memory` and `non_blocking`

Training on a GPU is fastest when the GPU doesn't have to wait for the CPU to load data.

  * `x.pin_memory()`: This allocates the `x` tensor in a special "pinned" (or page-locked) region of CPU RAM. Data in pinned memory can be transferred to the GPU much faster.
  * `.to(device, non_blocking=True)`: This initiates an **asynchronous** transfer. The CPU tells the GPU "start copying this data" but *doesn't wait* for it to finish. The CPU can immediately move on to its next task (like fetching the *next* batch), while the data transfer happens in the background.

This process overlaps data loading and model computation, minimizing GPU "idle" time and maximizing training speed.

## 5\. Model Architecture: A Detailed Look

The model is a standard GPT (Generative Pre-trained Transformer) with a **decoder-only** architecture. Our configuration is:

  * `n_layer = 6`: 6 Transformer blocks stacked on top of each other.
  * `n_head = 6`: 6 attention heads in each MHA layer.
  * `n_embd = 384`: The embedding dimension. This is the "width" of the model.

### 5.1. Token and Positional Embeddings

**Input `idx` Shape:** `(B, T)` -\> `(32, 128)` (Batch Size, Context Size)

1.  **Token Embedding (`wte`):**

      * This is a lookup table (`nn.Embedding`) of shape `(vocab_size, n_embd)` -\> `(50257, 384)`.
      * It maps each integer token ID (e.g., `539`) to a 384-dimensional vector that represents its "meaning."
      * **Shape Change:** `(B, T)` -\> `(B, T, C)` or `(32, 128, 384)`.

2.  **Positional Embedding (`wpe`):**

      * Transformers are "permutation-invariant"—they don't know the order of tokens. We must inject position information.
      * This model uses **learned absolute positional embeddings**.
      * `wpe` is another `nn.Embedding` lookup table of shape `(block_size, n_embd)` -\> `(128, 384)`.
      * The code generates `pos = torch.arange(0, t, ...)` (a tensor `[0, 1, 2, ... 127]`).
      * `wpe(pos)` looks up the embedding vector for each position.
      * **Shape:** `(T, C)` or `(128, 384)`.

3.  **Combining Embeddings:**

      * The token embeddings (`tok_emb`) and positional embeddings (`pos_emb`) are simply **added together**.
      * `x = self.transformer.drop(tok_emb + pos_emb)`
      * PyTorch broadcasting handles the addition: `(B, T, C) + (T, C)` -\> `(B, T, C)`.
      * The resulting tensor `x` now contains vectors that represent both the *token's meaning* and its *position in the sequence*.

### 5.2. Layer Normalization (LayerNorm)

Layer normalization is crucial for stabilizing the activations in deep transformers. It is applied *before* the main sub-layers (a "pre-norm" architecture).

  * **How it works:** Unlike Batch Norm (which normalizes across the batch), Layer Norm normalizes **across the features** for *each token independently*.
  * **Input:** A tensor `x` of shape `(B, T, C)` -\> `(32, 128, 384)`.
  * **Operation:** For *each* of the `B * T` tokens (e.g., for the token at batch `5`, position `20`), `LayerNorm` computes the `mean` and `variance` of its `C=384` features.
  * It then normalizes that token's vector: `(x - mean) / sqrt(variance + 1e-5)`.
  * Finally, it applies two learned parameters, `weight` (scale) and `bias` (shift), to restore the model's representational power.
  * This ensures that the inputs to the attention and MLP layers are always well-scaled, which leads to more stable training.

### 5.3. Causal Multi-Head Self-Attention

This is the core of the Transformer. "Self-Attention" means tokens in the sequence "look at" and "gather information from" other tokens in the *same sequence*.

1.  **Q, K, V Projection:**

      * The input `x` (shape `(B, T, C)`) is fed into *one* large `nn.Linear` layer (`c_attn`) that projects it from `C` to `3*C`.
      * **Shape Change:** `(32, 128, 384)` -\> `(32, 128, 3 * 384)`.
      * This `(B, T, 3*C)` tensor is then `split` into three separate tensors: **Query (`q`), Key (`k`), and Value (`v`)**, each of shape `(B, T, C)`.

2.  **Splitting into Heads:**

      * The model uses `n_head = 6`. The embedding `C=384` is split among these heads.
      * **Head Dimension (`d_head`):** `C / n_head` = `384 / 6 = 64`.
      * Each `q`, `k`, and `v` tensor is reshaped to `(B, T, n_head, d_head)` and then transposed to `(B, n_head, T, d_head)`.
      * **Shape:** `(32, 6, 128, 64)`.
      * Now, each of the 6 heads independently performs attention on a 64-dimensional slice of the token vectors.

3.  **Scaled Dot-Product Attention (The `else` block):**

      * **A) Attention Scores:** `att = (q @ k.transpose(-2, -1))`
          * Shape: `(B, H, T, d_k) @ (B, H, d_k, T)` -\> `(B, H, T, T)`
          * Shape: `(32, 6, 128, 64) @ (32, 6, 64, 128)` -\> `(32, 6, 128, 128)`
          * This `(T, T)` matrix computes the "similarity" score between every token's Query (`q`) and every other token's Key (`k`).
      * **B) Scaling:** `* (1.0 / math.sqrt(k.size(-1)))`
          * The scores are divided by $\sqrt{d_k}$ (i.e., $\sqrt{64} = 8$). This keeps the variance of the scores at 1, preventing the `softmax` function from saturating (which would kill gradients).
      * **C) Causal Masking:** `att = att.masked_fill(self.bias[:, :, :T, :T] == 0, float('-inf'))`
          * This is the **"causal"** part. We need to ensure that a token at position `i` cannot "see" or "get information from" a token at a *future* position `j > i`.
          * `self.bias` is a triangular matrix of `1`s and `0`s. The `0`s are in the **upper triangle**.
          * `masked_fill` sets all scores in the upper triangle to `-inf`.
          * When `softmax` is applied, `exp(-inf)` becomes `0`.
          * **Result:** The attention score from token 5 to token 8 is 0. The model *cannot* "cheat" by looking at the future tokens it is supposed to be predicting.
      * **D) Softmax:** `att = F.softmax(att, dim=-1)`
          * Converts the scores for each token into a probability distribution (summing to 1). This is the "attention weight."
      * **E) Apply to Values:** `y = att @ v`
          * Shape: `(B, H, T, T) @ (B, H, T, d_v)` -\> `(B, H, T, d_v)`
          * Shape: `(32, 6, 128, 128) @ (32, 6, 128, 64)` -\> `(32, 6, 128, 64)`
          * This is a weighted sum. The output for each token is the sum of all other tokens' `v` vectors, weighted by the attention probabilities.

4.  **Combine Heads and Project:**

      * The heads are combined: `y.transpose(1, 2).contiguous().view(B, T, C)`
      * Shape: `(32, 6, 128, 64)` -\> `(32, 128, 6, 64)` -\> `(32, 128, 384)`.
      * This concatenated tensor is passed through a final linear layer `c_proj` to produce the output.
      * **Flash Attention:** The `if self.flash:` block uses `F.scaled_dot_product_attention`, a new, highly optimized PyTorch function that performs steps A-E in a single, memory-efficient kernel, which is much faster.

### 5.4. The MLP (Position-wise Feed-Forward) Block

After the attention layer, the output (after another `LayerNorm`) is passed to a simple Multi-Layer Perceptron (MLP).

  * This MLP is applied **independently to each token** (it is "position-wise").
  * `self.c_fc`: A Linear layer that expands the dimension from `C` to `4 * C` (from 384 to 1536).
  * `self.gelu`: The GELU activation function is applied. It's a smooth alternative to ReLU.
  * `self.c_proj`: A Linear layer that projects the dimension back down from `4 * C` to `C`.
  * This two-layer network "processes" the information gathered by the attention layer, adding more computational depth.

### 5.5. The Full Transformer Block

The `Block` class defines the full transformer layer. It uses a **pre-norm** architecture:

```python
def forward(self, x):
    x = x + self.attn(self.ln1(x))  # Normalize -> Attend -> Add residual
    x = x + self.mlp(self.ln2(x))   # Normalize -> MLP -> Add residual
    return x
```

The `x = x + ...` is the **residual (or skip) connection**. It allows the gradient to flow directly through the network, which is critical for training deep models.

## 6\. Training and Loss Calculation

### The Language Model Head

After the input has passed through all 6 `Block` layers and a final `ln_f` (LayerNorm), the model produces a final output `x` of shape `(B, T, C)`.

  * `self.lm_head`: This is the final `nn.Linear` layer. It projects the embedding `C` (384) up to the `vocab_size` (50,257).
  * **Shape Change:** `(B, T, C)` -\> `(B, T, vocab_size)`
  * This final tensor, `logits`, contains the raw, unnormalized scores for *every possible token in the vocabulary*, for *every position in the batch*.
  * **Weight Tying:** The code uses `self.transformer.wte.weight = self.lm_head.weight`. This forces the input embedding matrix (`wte`) and the output projection matrix (`lm_head`) to share the same weights. This reduces the number of parameters and is a standard practice that improves performance.

### Loss Function: Cross-Entropy

We use `F.cross_entropy` to calculate the loss.

```python
loss = F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1), ignore_index=-1)
```

1.  **Reshaping:**
      * `logits.view(-1, logits.size(-1))` reshapes `logits` from `(B, T, vocab_size)` to `(B*T, vocab_size)`.
      * `targets.view(-1)` reshapes `y` from `(B, T)` to `(B*T)`.
2.  **What `cross_entropy` does:**
      * It internally applies `LogSoftmax` to the `logits` to get log-probabilities.
      * It then uses `NLLLoss` (Negative Log Likelihood Loss) to pick out the log-probability corresponding to the *correct* token ID from our `targets`.
      * The loss is the *average* of these negative log-probabilities.
      * **Goal:** Minimizing this loss forces the model to assign a higher and higher probability to the correct next token.

### Backpropagation and Optimization

1.  **Mixed Precision (`ctx`):** `with torch.amp.autocast(...)` tells PyTorch to run operations in `bfloat16` or `float16` (half-precision) where possible. This is much faster and uses less GPU memory.
2.  **Gradient Scaling (`scaler`):** When using `float16` (which has a very small dynamic range), gradients can "underflow" (become zero). `GradScaler` prevents this:
      * `scaler.scale(loss).backward()`: It scales the loss by a large factor (e.g., 65536) *before* `backward()`, so the gradients are also large and don't become zero.
3.  **Gradient Accumulation:**
      * `loss = loss / gradient_accumulation_steps`: We scale the loss down so that when we sum gradients over `gradient_accumulation_steps` (32), the average is correct.
      * `optimizer.step()` is only called every `gradient_accumulation_steps` loops.
      * This simulates a much larger batch size (`effective_batch_size = 32 * 32 = 1024`) without using more GPU memory.
4.  **Gradient Clipping:** `torch.nn.utils.clip_grad_norm_(...)` prevents "exploding gradients" by clamping their maximum value.
5.  **Optimizer Step:**
      * `scaler.step(optimizer)`: *Before* updating weights, the scaler checks for `inf` gradients (which can happen in mixed precision) and *un-scales* the gradients back to their original size.
      * `scaler.update()`: Updates the scaling factor for the next iteration.
      * `optimizer.zero_grad(set_to_none=True)`: Clears the gradients for the next accumulation cycle.
      * `scheduler.step()`: Updates the learning rate based on the warmup and cosine decay schedule.

## 7\. How to Run

1.  **Setup:**
    Install the required libraries:

    ```bash
    pip install ipykernel torch numpy datasets tiktoken tqdm matplotlib
    ```

2.  **Data Preparation (First Run):**
    Simply run the first few cells. The script will:

      * Download `roneneldan/TinyStories`.
      * Tokenize the dataset (this may take several minutes).
      * Create the `train.bin` and `validation.bin` files in your directory.
      * This step is skipped on subsequent runs if the `.bin` files already exist.

3.  **Training:**
    Run the cells defining the model, config, and training loop. The script will:

      * Initialize the `GPT` model and `AdamW` optimizer.
      * Begin the training loop for `max_iters` steps.
      * Periodically print the `train loss` and `val loss`.
      * Save the best-performing model weights to `best_model_params.pt` based on the validation loss.

4.  **Generation:**
    Run the final cells to:

      * Load the saved `best_model_params.pt` weights.
      * Provide a prompt (e.g., `"Once upon a time there was a pumpkin."`).
      * Generate `200` new tokens, decoding them back into text.
